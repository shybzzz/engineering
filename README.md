# Engineering

Особистий маркетплейс для Claude Code: скіли, команди та агенти, які я перевикористовую у всіх проєктах.

## Структура

```
engineering/
├── .claude-plugin/
│   └── marketplace.json          # каталог маркетплейсу
└── plugins/
    ├── toolkit/                  # мій базовий плагін
    │   ├── .claude-plugin/
    │   │   └── plugin.json       # маніфест плагіна
    │   └── skills/
    │       ├── save-skill/            # «збережи цей скіл у хмарі» → автозбереження сюди
    │       │   └── SKILL.md
    │       ├── conventional-commit/   # коміти за Conventional Commits
    │       │   └── SKILL.md
    │       └── ua-docs-style/         # стиль українських інженерних документів
    │           └── SKILL.md
    ├── maker/                    # виготовлення фізичних речей (3D-друк)
    │   ├── .claude-plugin/
    │   │   └── plugin.json
    │   └── skills/
    │       └── printable-3d-model/    # (EN) 3D-модель для друку: вимірювання → генерація (mesh або FreeCAD B-rep) → перевірка
    │           ├── SKILL.md
    │           └── scripts/
    │               ├── stl_info.py    # інспекція STL (stdlib): розміри, z-min, manifold
    │               └── mesh_kit.py    # шаблон генератора watertight STL (shapely + fonttools)
    └── teacher/                  # викладацька робота
        ├── .claude-plugin/
        │   └── plugin.json
        └── skills/
            ├── methodology-doc/       # (EN) методичка з теми курсу: теорія з рисунками → алгоритм → приклад → задачі зі скрипт-перевіреними відповідями → Claude Doc у двох мовах
            │   └── SKILL.md
            └── syllabus/              # (EN) силабус дисципліни: ОПП/ОНП → зміст → .docx за шаблоном кафедри → перевірка
                ├── SKILL.md
                └── scripts/
                    ├── syllabus_docx.py   # inspect / extract / build / selftest (python-docx)
                    └── docx2pdf.ps1       # .docx → PDF через Word для візуальної перевірки (Windows)
```

## Скіли

### Плагін `toolkit`

| Скіл | Коли спрацьовує | Що робить |
|------|-----------------|-----------|
| `save-skill` | «збережи цей скіл у хмарі», «збережи в маркетплейс», «створи новий плагін у хмарі» | Обирає плагін за темою (`maker` для фізичних речей, `teacher` для викладацької роботи, інакше `toolkit`) або створює новий; створює/оновлює SKILL.md у цьому репозиторії, прибираючи проєктну специфіку; переписує скіл-джерело в проєкті так, що він посилається на скіл маркетплейсу і містить лише проєктні деталі; піднімає версію плагіна, оновлює README, комітить і пушить. |
| `conventional-commit` | будь-який коміт у проєктах користувача, «закоміть» | Пише повідомлення комітів за стандартом Conventional Commits. |
| `ua-docs-style` | створення/редагування/перевірка українських інженерних документів у стилі наукової статті | Структура статті (Анотація → розділи → Висновки → Література), LaTeX-математика з нумерацією формул, нумерація рисунків і таблиць, термінологія, перевірені джерела з DOI через Crossref, правила для Confluence-сторінок. |

### Плагін `maker`

| Скіл | Коли спрацьовує | Що робить |
|------|-----------------|-----------|
| `printable-3d-model` | «зроби 3D-модель для друку», «згенеруй STL», «зроби лоток/бокс/підставку під …», «виміряй STL», «чому non-manifold», «чи влізе на столик», «деталь туга/болтається/треться/потребує підтримок» (текст скіла — англійською) | Повний цикл: вимірювання вхідних STL/STEP/3MF (пастки: z-min ≠ 0, нелінійний масштаб, назви), конструювання під FDM без підтримок у орієнтації друку (навіси ≥ 45°, без отворів у мостах, кишені наскрізні/вгору), перевірка складальності (шляхи встановлення, доступ до кріплення), посадки й купон підгонки, підшипники/колеса/напрямні по шнуру; два шляхи генерації — watertight STL кодом (`mesh_kit.py`) або параметричний FreeCAD-генератор (`params.json` + `derive()` + варіанти, STEP у орієнтації друку, перевірка інтерференцій, повторне використання надрукованих деталей); обов'язкова перевірка manifold, прев'ю, звіт, цикл «друк → симптом → параметр». |

### Плагін `teacher`

| Скіл | Коли спрацьовує | Що робить |
|------|-----------------|-----------|
| `methodology-doc` | «зроби методичку», «створи методичку з теми …», «методичка у формі артефакту», «методичку польською і українською», «зроби задачі з відповідями для студента», "make a study guide for the student" (текст скіла — англійською) | Методичка з однієї теми курсу як Claude Doc з вкладкою-перекладом: збір джерел (силабус, фото зошита, нотація викладача, наявна методичка як зразок формату), фіксована структура (вступ із таблицею позначень → нумерована теорія з рисунками → покроковий алгоритм за чек-листом викладача → розібраний приклад із зошита → задачі → відповіді → перевірена література), скрипти в `tools/<topic>/` (генератор задач із двома незалежними розв'язувачами й балансом, рисунки schemdraw/matplotlib з панелями для кожної мови, повний текст вкладок у md), порядок запису в Claude Docs (каркас → розділ за викликом → таблиці → блоби рисунків → вкладка перекладу; ліміт 32 КБ на запис), контрольний список перевірки та правила розширення наявної методички. |
| `syllabus` | «створи/онови силабус», «зроби силабус з дисципліни …», «синхронізуй силабус з ОПП», «перенеси силабус у новий формат», «онови літературу в силабусі», «додай викладача в силабус» (текст скіла — англійською) | Повний цикл: визначення освітньої програми та її редакції (якщо потрібної редакції не опубліковано — питає), читання ОПП/ОНП і навчального плану (матриці компетентностей — лише як зображення), ЗК/ФК/ПРН дослівно, зв'язки з іншими компонентами, мета й цілі під мету програми, години за навчальним планом, викладачі (посада ≠ вчене звання), перевірена література (15–20 джерел, основні не старші 5 років, електронні ресурси), критерії оцінювання і схема курсу; збирання .docx із шаблону кафедри скриптом `syllabus_docx.py` (зміст у JSON, автонумерація літератури, перевірки годин, віку джерел і залишків шаблону), візуальна перевірка через PDF, звіт про джерела даних і незаповнені поля. |

## Перший запуск (один раз)

1. Створи порожній репозиторій на GitHub (можна приватний), наприклад `engineering`.
2. Запуш цю папку туди:
   ```bash
   cd engineering
   git remote add origin git@github.com:shybzzz/engineering.git
   git push -u origin main
   ```
3. Встав свій справжній `shybzzz` у:
   - `plugins/toolkit/skills/save-skill/SKILL.md` (рядок MARKETPLACE_REPO)
   - цей README
4. Підключи маркетплейс у Claude Code:
   ```bash
   claude plugin marketplace add shybzzz/engineering
   claude plugin install toolkit@engineering
   ```
   (або всередині сесії: `/plugin marketplace add ...` та `/plugin install toolkit@engineering`; при встановленні обирай scope **user** — щоб плагін був у всіх твоїх сесіях)

## На кожній новій машині

```bash
claude plugin marketplace add shybzzz/engineering
claude plugin install toolkit@engineering
claude plugin install maker@engineering
claude plugin install teacher@engineering
```

## Щоденне використання

- **Зберегти знання з розмови:** скажи Claude «збережи цей скіл у хмарі» — спрацює скіл `save-skill`, і Claude сам створить SKILL.md, закомітить і запушить сюди.
- **Підтягнути оновлення на іншій машині:** `/plugin marketplace update engineering`.
- **Локальні правки без пушу:** редагуй файли і виконай `/reload-plugins` у сесії.
- **Перевірка валідності:** `claude plugin validate .` з кореня репозиторію.

## Додати новий скіл вручну

1. Створи папку `plugins/<плагін>/skills/<назва-скіла>/` з файлом `SKILL.md` (`toolkit` — загальні робочі скіли, `maker` — все про виготовлення фізичних речей, `teacher` — викладацька робота):
   ```markdown
   ---
   name: назва-скіла
   description: Одне-два речення — КОЛИ використовувати скіл, з тригер-фразами.
   ---

   # Інструкції для моделі...
   ```
2. Підніми `version` у `plugins/<плагін>/.claude-plugin/plugin.json`.
3. Додай скіл у дерево структури та таблицю «Скіли» в цьому README.
4. Закоміть і запуш.

## Claude Desktop (Cowork)

У налаштуваннях плагінів Desktop-застосунку додай маркетплейс, вказавши `shybzzz/engineering`, і встанови `toolkit`, `maker` та `teacher` зі списку — ті самі скіли працюватимуть і там.
